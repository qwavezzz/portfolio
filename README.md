# qwave — Personal Space

Первый рабочий прототип персонального портфолио: настоящая 3D-сцена, рабочий стол с ASCII-графикой и отдельные разделы в SPA-подходе.

Подтверждено имя **qwave** и добавлен первый проект — [сайт компании «Дары Синергии»](https://dari-sinergii.ru). Биография, услуги, цены и контакты пока не предоставлены; соответствующие разделы показывают пустые состояния. До завершения наполнения выставлен `noindex, nofollow`.

## GitHub Pages

Адрес сайта: **https://qwavezzz.github.io/portfolio/**. Workflow `.github/workflows/deploy.yml` собирает и публикует сайт при каждом push в `main`; его можно запустить вручную во вкладке Actions. Источник в настройках Pages — GitHub Actions.

Локально сайт работает от `/`. Для проверки размещения в подпапке используйте `SITE_BASE=/portfolio`; внутренние ссылки, заставки и модель получают префикс через `src/lib/paths.ts`.

```powershell
$env:SITE_BASE='/portfolio'
npm.cmd run build
npm.cmd run preview -- --port 4323
$env:PAGES_URL='http://127.0.0.1:4323/portfolio/'
npx.cmd playwright test tests/github-pages.spec.ts
```

Для проверки опубликованного сайта укажите в `PAGES_URL` его полный адрес. После локальной проверки удалите переменную `SITE_BASE`, чтобы вернуться к корневому адресу разработки.

## Запуск

Проверено на Node.js 24.18.0 и npm 11.16.0. Используется один менеджер пакетов — npm; точные версии сохранены в `package-lock.json`.

```powershell
npm.cmd ci
npm.cmd run dev
```

Адрес разработки: `http://127.0.0.1:4321`. На macOS/Linux используйте `npm` вместо `npm.cmd`. Скрипт запуска отключает необязательную телеметрию Astro, чтобы сборка не требовала записи в системные каталоги.

```powershell
npm.cmd run build
npm.cmd run preview -- --port 4322
```

Сборка находится в `dist/`. Astro 7 может запускать сервер в фоне в агентской среде. Остановка:

```powershell
node scripts/astro.mjs dev stop
node scripts/astro.mjs preview stop
```

## Где менять содержание

Все личные данные находятся в [src/data/portfolio.ts](src/data/portfolio.ts): `profile`, `projects`, `services`, `contacts`. Не нужно изменять сцену, чтобы добавить работу.

Пример формы записи (подставьте собственные сведения и реальный URL):

```ts
{
  id: 'unique-project-id',
  title: 'Название вашей работы',
  summary: 'Задача и результат проекта',
  role: 'Ваша роль',
  url: 'https://your-project-domain.example',
  icon: 'browser', // browser | folder | file
  order: 1,
  draft: true, // смените на false после заполнения и проверки URL
}
```

`draft: true` исключает работу из вывода. Активные проекты проверяются при сборке и появляются ярлыками внутри папки «Портфолио» на рабочем столе. Папка открывается одним нажатием без смены страницы; ярлык проекта открывает сайт в новой вкладке. Крестик и Escape закрывают папку и возвращают фокус на её ярлык. Без JavaScript доступно раскрытие через HTML `details`. Если работ нет, папка показывает «Здесь появятся мои работы».

Услуги: `id`, `title`, `description`, `price` — строка с согласованной ценой и валютой, например формат «от … ₽». Если суммы ещё нет, используйте «Стоимость уточняется». Контакты: `label`, `display`, `url`; допустимы HTTP(S), `mailto:` и `tel:`. Поля никогда не вставляются как произвольный HTML.

После заполнения и перед публикацией: проверить тексты, URL, суммы; добавить настоящий домен, canonical, абсолютный Open Graph URL/изображение, robots.txt и sitemap. Сейчас домен не выдуман, сайт не опубликован.

## Сцена и графика

Сцена создана в Blender по композиции `references/7.jpg`: два монитора, широкий стол, кресло с сетчатой спинкой, книги, кружка, наушники, стеллаж и растение. За окном находится исходный `references/8.jpg`, встроенный в одну плоскость; город не моделируется. Геометрия и экранная графика qwave созданы для проекта. Детали генерации, координаты и команды пересборки: [assets-source/README.md](assets-source/README.md).

После оптимизации GLB весит около 2,37 МБ: 17 mesh-групп, 92 614 треугольников, три встроенные текстуры. `scripts/optimize-model.mjs` выполняет weld/dedup/prune/quantize и проверяет координаты основного экрана и точное совпадение JPEG-фона с исходником. Внешний декодер не нужен. Для desktop и mobile рендерятся отдельные заставки; `scripts/optimize-poster.mjs` воспроизводит WebP из PNG. Числа и размеры текстур записаны в [assets-source/model-report.json](assets-source/model-report.json).

R3F загружается отдельно. Сцена рендерится по необходимости; при уходе с экрана и в скрытой вкладке рендер останавливается. При reduced-motion, ошибке GLB/рендера или ручном отключении остаётся заставка. Выбор статичного режима сохраняется в localStorage, когда хранилище доступно. Геометрия и текстуры кешируются для повторного входа; новый WebGL-контекст не нужен на внутренних страницах.

На узких экранах и устройствах с сенсорным вводом сцена использует DPR 1, карту теней 1024×1024 и отключённое MSAA. Инициализация R3F выполняется через `createRoot().configure()` с обработкой отклонённого Promise: в используемой версии `Canvas` ошибка создания WebGL-контекста могла обходить React error boundary. При потере контекста во время пролёта восстанавливаются обычный HTML и положение рабочего стола. События resize без изменения размеров сцены не запускают принудительную прокрутку.

Плакат и живая сцена имеют общую геометрию и камеру, но освещение Cycles и WebGL немного отличается. Основной переход — приближение камеры к экрану по прокрутке. CSS удерживает сцену, GSAP ScrollTrigger связывает пройденное расстояние с камерой. `src/lib/monitor-flight.ts` совмещает настоящий HTML-рабочий стол с четырьмя углами экрана через проективное преобразование. В конце он занимает весь браузер и становится интерактивным; обратная прокрутка возвращает общий план. Кнопка входа и `/#desktop` пропускают движение, запасные режимы сохраняют обычный HTML.

Живой HTML-рабочий стол виден на мониторе с первого кадра: в активной сцене он заменяет статичную текстуру `Screen`. До выхода в полный экран он находится внутри закреплённой сцены, поэтому прокрутка документа не сдвигает его относительно камеры. Камера, проекция HTML и WebGL обновляются одним вызовом R3F `advance`; повторные запросы объединяются в один кадр. В конце тот же DOM-элемент возвращается в обычный поток страницы.

При навигации длина пролёта восстанавливается внутри `astro:before-swap` до восстановления прокрутки браузером. Загрузка GLB не меняет геометрию страницы. Кнопки браузера «Назад/Вперёд» сохраняют положение как на рабочем столе, так и посреди пролёта; фокус ярлыка хранится в соответствующей записи истории. Сцена загружается и при входе через `/#desktop`, чтобы обратная прокрутка оставалась доступной.

После 72% пролёта при прокрутке вниз [ScrollTrigger snap](https://gsap.com/docs/v3/Plugins/ScrollTrigger/) плавно доводит переход до полностью интерактивного рабочего стола. Задержка — 180 мс, длительность — 200–450 мс; удержание пальца и обратная прокрутка не должны запускать доведение. После входа содержимое рабочего стола прокручивается свободно.

ASCII-композиция на страницах генерируется детерминированно в `src/lib/ascii.ts`. Шрифты Golos Text и IBM Plex Mono обслуживаются локально из установленных Fontsource-пакетов. Лицензии: соответствующие `node_modules/@fontsource*/…/LICENSE` и официальные репозитории, указанные в DESIGN.md. Референсы используются как направление и не включаются в публичную сборку.

## Проверки

```powershell
npx.cmd playwright install chromium
npm.cmd run preview -- --port 4322
$env:PREVIEW_URL = 'http://127.0.0.1:4322'
npm.cmd test
```

При наличии собственного Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE` полным путём к исполняемому файлу. Для захвата изображений: `node scripts/capture.mjs` с теми же переменными; результаты находятся в `.impeccable/review/`.

Для проверок в WebKit установите `npx.cmd playwright install webkit`, задайте `$env:PLAYWRIGHT_BROWSER = 'webkit'` и запустите `npm.cmd test`. Для возврата к Chromium: `Remove-Item Env:PLAYWRIGHT_BROWSER`. Регрессии в `tests/monitor-flight.spec.ts` покрывают snap, отказ создания WebGL, потерю контекста посреди/после пролёта и повторные resize. Проверка свайпа с удержанием пальца использует CDP и выполняется только в Chromium. WebKit в Playwright не заменяет проверку внутри Telegram на реальном iPhone; точная причина исходного сбоя Telegram пока не подтверждена.

Проверяются пролёт внутрь монитора на desktop/mobile, обратная прокрутка, изменение высоты окна и пропуск; также переходы без перезагрузки, прямые адреса, возврат/история/фокус, клавиатура, отключённый JS, reduced-motion, отказ модели, сохранение выбора 3D, ошибка перехода, 404 и отсутствие горизонтального переполнения на 360/390/768/1440px. `tests/monitor-flight.spec.ts` сохраняет четыре стадии пролёта для обеих ширин в `.impeccable/review/flight-*.png`. Условия и ограничения итоговой проверки — в [design/VALIDATION.md](design/VALIDATION.md).

Impeccable 4.3.1 применён для принятого дизайн-кода, направления реализации, проверки craft-floor, одного механического прохода `detect --json src` и финального просмотра. Механический детектор вернул пустой список. Это не заменяет браузерные тесты и визуальный разбор.

## Размещение

Публикуйте `dist/` на статическом HTTPS-хостинге. Адреса `/about/` и `/contact/` должны отдавать свои `index.html`; для отсутствующих путей настройте `404.html` со статусом 404. Тотальный rewrite на главную здесь не нужен. Всё 3D и шрифты обслуживаются с того же домена. `assets-source/`, `references/`, тесты и документы в `dist/` не попадают.

Бюджеты LCP/FPS из ТЗ пока не заявлены как достигнутые: нужны измерения на реальном компьютере и телефоне с заданным профилем сети. Автоматические снимки проверены в Chromium на Windows; Safari/iPhone, Android и Firefox требуют отдельного прохода перед публикацией.
